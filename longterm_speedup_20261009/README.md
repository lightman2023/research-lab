# 長期学習向けの追加高速化（2026-10-09）

## 結果と適用

正本は /home/user/chess/alphazero_chess_v2。前回の高速化済みコードを基準に追加実装した。GPUで8局面をそれぞれ800探索した処理時間は、現行版の逐次処理27.75秒、新版の2同時処理11.62秒、8同時処理5.44秒。これは8局面の探索の比較で、旧2プロセス並列との1サイクル全体の速度比ではない。800探索の測定は各1回、200探索は各2回。モデルは保存B50、RTX 3060、実棋譜の終局5半手前8局面、ノイズあり、各局面のシード90100+番号で比較した。

本番モデルや既存NPZを編集・削除する操作は行っていない。本番の継続学習自体は稼働しているため、その通常の保存・更新は進む。前回の提案10項目のうち1～9を実装した。10の半精度計算は、数値精度が変わるため今回は採用していない。

## 数値差と検証範囲

単独の探索では旧版と訪問回数が一致。過去の盤面入力・終局判定は棋譜48局や特殊手を含む3,118局面で完全一致した。

複数局面をGPUでまとめると、GPUの計算のまとめ方による数値差がある。2同時以上のバッチ版はfloat32のhighest積精度を指定してTF32近似を抑える。800探索の8局面では、最多訪問の手はすべて旧版と同じ、個々の手の訪問差は最大2回、訪問分布の全変動距離は最大0.00375（0.375%の確率質量）だった。これはGPUでの全対局の指し手が必ず一致する保証ではない。1同時なら既存の単独推論を使い、200探索の比較で訪問回数・評価が一致している。

| 比較・検証 | 結果 |
|---|---|
| 現行版と差分履歴版、GPU200探索 | 初期局面で約1.04倍、310半手履歴の終盤で約1.48倍。訪問回数一致 |

実際の1サイクル全体の短縮率や長期の強さは未測定。今後のGUIログでサイクル時間を確認できる。改良による速度比は重複する処理があるため、個別の倍率を掛け合わせて全体速度を予測しない。

## 保存・再開と切り戻し

現在の学習先は従来のexperiments/search-budget-20261004/B200。完了した対局とそのシードを確認し、未完了番号だけ生成する。停止したバッチ処理の再実行でも完成済みのNPZは再利用する。途中サイクルの探索回数はcycle_settingsで維持し、変更した探索回数は次サイクルから適用する。

旧方式のランチャーは parallel_selfplay.py --engine legacy。コンパイルキャッシュを無効にする場合はAZCHESS_DISABLE_COMPILATION_CACHE=1。検証キャッシュは元NPZを基に再作成できる補助情報。手動で修復する場合も本番NPZやモデルを削除する必要はない。

既存ソースのバックアップは正本の同名ファイル.pre-longterm-speedup-20261009。変更対象はazchess/mcts.py、checkpoint.py、history.py、batched.py、runtime.py、data_cache.py、train.py、parallel_selfplay.py、batched_selfplay.py、check_search_cycle.py、verify_raw_visit_data.py、monitor_experiment.pyとWindows追加学習GUI。新規ファイルはbaselineに存在しない。baseline/とcandidate/に比較用コード、各validation.jsonとログに測定結果を保持。deployment.jsonは初回反映の記録、final_deployment.jsonは最終版のハッシュ記録。

主な再現用スクリプト：verify_history.py、verify_and_benchmark.py --gpu、benchmark_batch.py --simulations 800 --workers 2,8 --repeats 1、verify_training.py、verify_selfplay.py、verify_cache.py、verify_monitor_stats.py。verify_training.pyは再実行時点の本番状態を再コピーするため、今回の固定条件は保存したJSONとfrozen_data/を参照する。

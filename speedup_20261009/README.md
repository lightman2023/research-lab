# チェスv2学習の高速化（2026-10-09）

## 変更と対象

正本：WSL /home/user/chess/alphazero_chess_v2。稼働中のB200追加学習は800探索、8対局、2並列、64更新。既存の実験・保存形式・学習率・温度・反復ルールを維持した実装の高速化である。

変更ファイル：azchess/mcts.py、azchess/game.py、train.py。反映直前に正本と保存した旧版のSHAが一致することを照合し、.pre-speedup-20261009に旧版を保存した。正本への反映はdeployment.jsonに記録。実行中のPythonプロセスは既に読み込んだ旧版を使って完了する。新しく起動する自己対局・学習プロセスは自動で新版を使う。GUIの再起動やモデルの初期化は不要。

### モデル重みの配置

旧版のチェックポイント読込結果は81個のNumPy配列（合計4,502,968バイト）。各探索葉でJIT関数にこれらを渡していた。新版はMCTS初期化時にjax.device_putで計算デバイスに配置し、毎回の重み転送を避ける。入力・出力の型や精度、モデル構造は変更していない。推論出力はまとめてホストへ取り出してからスライスし、出力スライスの追加JAX処理も減らした。

### 局面履歴のコピー

旧版はシミュレーションごとに全履歴つき盤面をコピーしていた。新版は探索開始時に1回コピーし、各シミュレーション後にpushした手をpopして戻す。実対局の履歴と8履歴の入力、反復判定は保持する。局面エンコーダ自体の履歴処理は変更していない。

### 合法手とデータ読み込み

legal_action_mapの合法手生成を1回にまとめた。重複する行動番号のチェックは保持した。

学習データは使う5配列だけ読み込む。1つの読み込みスレッドで次のバッチを先読みし、現在のデバイス更新と重ねる。ReplayBufferの乱数生成を担当するのはこの1スレッドのみで、サンプル順序を変えない。先読みは1バッチまで。診断時はtrain.py --no-prefetchで無効にできる。

## 測定結果

共通モデル：B200保存50サイクル版、SHAはsearch_validation.jsonとsearch_gpu_validation.jsonに記録。ウォームアップ後に旧版・新版の順を交互にして各3回測定し中央値を使用。

| GPU・200探索 | 旧版中央値 | 新版中央値 | 速度比 |
|---|---:|---:|---:|
| 初期局面 | 6.002秒 | 1.105秒 | 5.43倍 |
| 310半手の履歴がある終盤 | 5.035秒 | 1.104秒 | 4.56倍 |

RTX 3060、既存の自己対局2プロセスが動いている環境で追加メモリを抑えて測定した。GPUの空き容量を測定前に確認。GPUでは200探索の局面ごとの速度を測定したものであり、800探索の対局全体やサイクル全体が同じ倍率になると確定した結果ではない。

CPU・800探索は3局面で1.21～1.35倍。プロファイルには307半手の履歴を持つ64探索のコストを記録。GPU版との速度差はデバイス転送負荷の違いを含む。

学習更新のCPU試験は実データ128局、バッチ64、4更新。起動・JITコンパイル込みで旧版16.09秒、新版14.79秒。短い試験なので長時間学習の速度比を表す数値としては扱わない。

## 正しさの検証

- CPU：4局面×ノイズ有無の8条件、200探索。各手の訪問回数が一致、事前確率・価値累積を許容差1e-6で照合。元の盤面・履歴も不変。
- GPU：2局面×ノイズ有無の4条件で同様に一致。
- 終局・特殊手：17局面、64探索、ノイズあり。キャスリング、アンパッサン、昇格、50手境界、三fold反復履歴、駒不足を含み、旧版と結果一致。実ネットを使わない決定的評価器で盤面管理と終局処理を比較した。
- 実学習：同じデータ128局の隔離コピー、同じモデル・再開状態、同じシード108009からバッチ64で4更新。パラメータ、BatchNorm統計、最適化状態を含む185配列を比較し最大差0、更新6272→6276。
- モデル・本番リプレイデータへの書込みは行っていない。検証用更新モデルはtraining_baseline/、training_candidate/に保存。

検証スクリプト：verify_and_benchmark.py（--gpuでGPU）、verify_rules.py、verify_training.py。元コードbaseline/、新版candidate/、各条件・結果JSON・ログをこのフォルダーに保持。verify_training.pyを再実行する場合は、その時点の本番データを読み直すため別の試験条件になる。

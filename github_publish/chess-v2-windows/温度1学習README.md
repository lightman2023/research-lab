# 低学習率・温度1の学習GUI

既存の訪問回数版GUIの構成を流用した、専用の起動入口です。

## 起動と実行

1. `C:/Users/User/Desktop/chess_v2/v2温度1学習を起動.bat` を開く。
2. 初期設定の「連続学習を開始」で10サイクルを実行する。
3. 画面内の実行ログで対局・学習・監視結果を見る。ログは `training_controller_v2_temp1.log` にも保存される。
4. 途中で止める場合は「停止」を押す。完了済みデータ・モデルは残る。

最初に「確認対局2局を実行」を選ぶこともできます。確認用の対局は `validation_data` に保存し、学習用データには混ぜません。

## 条件と保存先

- 保存先：`/home/user/chess/alphazero_chess_v2/experiments/live-lr0001-temp1-20261002`
- 開始モデル：前回の低学習率実験の10サイクル終了モデル。AdamWの学習状態（2240更新）も継続。
- 前回の学習用80局をコピーして引き継ぐ。前回の温度比較16局は含めない。
- 学習率0.0001で一定、全局面の手選択温度1、根のノイズα=0.3・混合率0.25。
- 初期設定：1サイクル8局・2並列・一手50探索・64更新・バッチ64・上限512半手。
- 初期設定は10サイクルで停止。連続回数0なら手動停止まで継続する。
- 最新モデルと学習状態は各サイクル更新。世代保存間隔は変更可能で、初期値1。有限回数で終了するときは、保存間隔に達していなくても最終モデルを保存する。
- 実際の3回反復・50手ルールで自動引き分け。学習する手の分布は加工前のMCTS訪問割合。教師の勝敗は終局結果。
- 新実験のcycle-000000は開始モデルで、前回実験のcycle-000010と同一。世代番号はこの追加実験内で数える。

## 監視

各サイクルの後に、固定129局面と学習データから抽出した128局面を調べる。
価値ヘッドの256成分が全て非正になりReLU出力が全てゼロの局面を数える。
どちらかの集合で10%以上になった場合、記録・モデルを保存して停止する。
この10%は診断用の独自設定で、AlphaZero論文の設定ではない。
記録には価値MSE、勝ち側・負け側・引き分けのラベル別の誤差、反復・詰み・50手ルール・上限打ち切りなどの終局理由を含める。
固定集合は過去の自己対局由来で、客観的な必勝・必敗の正解集ではない。強さは別の対局比較で確認する。

## 学習前後の比較

`v2モデル比較を起動.bat` のモデル一覧で「低学習率・温度1」を選ぶ。
開始モデルcycle-000000と終了モデルcycle-000010を選び、同じ探索50回・24局・白黒交換で比較する。
比較GUIは従来のものを使用し、今回のモデルを一覧に追加した。
自己対局・学習・監視中にはモデル比較を同時実行しない。

## 実装と検証

- `parallel_selfplay.py` が温度・seed・実験サイクル番号を `selfplay.py` に渡すようにした。
- GUIは `train.py --learning-rate 0.0001 --constant-learning-rate` で保存状態に対応したAdamWを使う。
- GUIの10サイクル処理・最終世代保存・確認用データの分離は、実際の長時間処理を置き換えたテストで確認。
- 実際の自己対局1局（探索2回・最大40半手）は31半手で終了。温度1・seed・サイクル番号が保存データへ届くことを確認。
- 別の確認用コピーで1更新し、2240更新から2241更新への再開を確認。実験本体のモデル・状態は変更していない。
- 初期モデルの監視結果は `metrics/cycle-000000.json`。検証結果は `validation_results.json`。
- Windows側のGUI初期化を確認。10サイクルの本学習は2026-10-02 23:20に完了。

設定は `configuration.json`、コピーした80局の由来とハッシュは `carried_data_manifest.json`、各サイクルの監視結果は `metrics/cycle-*.json` に保存する。GUIの実行ログに主要なコマンド・進捗・監視結果を残す。

手選択温度1の背景：David Silver, Thomas Hubert, Julian Schrittwieserほか（2017）、*Mastering Chess and Shogi by Self-Play with a General Reinforcement Learning Algorithm*、https://arxiv.org/html/1712.01815v1 、Configuration節の訪問回数比例の手選択。今回の学習率・規模・監視閾値は独自の試験条件で、論文の性能を再現したという意味ではない。

## 温度1の学習前後を選んだ比較入口

`v2温度1の学習前後を比較.bat` を開き、「比較対戦をスタート」を押す。
既存の比較GUIを使い、Aに温度1のcycle-000000、Bにcycle-000010を自動選択する。
初期条件は24局（12開始局面で白黒交換）、一手50探索、上限512半手。
自己対局時の温度1と異なり、評価では訪問回数最多の手を選ぶ。
勝敗・終局理由・半手数・打ち切りを画面内ログで確認できる。
ログはmodel_comparison_v2.log、棋譜は完了時に表示されるWSLのパスに保存される。
今回の学習前後比較はまだ実行していない。打ち切りや引き分けが多い場合は強さを断定しない。

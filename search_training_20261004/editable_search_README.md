# 追加学習GUIの探索回数変更（2026-10-08）

## 操作

1. 開いている古い追加学習GUIを閉じる。実行中なら停止が完了してから閉じる。
2. C:\Users\User\Desktop\chess_v2\探索学習比較_B200を起動.bat を開く。
3. 「一手の探索」に希望する整数（1～10000）を入力する。今回の希望値800を保存済み。
4. 「連続学習を開始」を押す。連続回数0なら停止するまで継続する。

設定は実行開始時に読み取り、実行中の入力欄は無効になる。さらに変更する場合は停止してから設定し直す。

## 途中再開

保存済みの対局があるサイクルは、元の探索回数で残りを生成する。希望する新しい回数は次のサイクルから適用される。これにより同一サイクル内で設定が混ざらず、保存済みの対局も保持できる。

今回確認した実状態：44サイクル学習完了、5696更新、45サイクル目の第1～6局を保存済み、全データ518局。希望800に対して、第7・8局は200探索、次の46サイクルから800探索となる。再開・長時間学習はこの修正検証では実行していない。

旧コードは200以外を開始前に拒否していた。旧コードが作った途中データには200を引き継ぐ。新しいサイクルごとの実使用設定はWSLの experiments/search-budget-20261004/B200/cycle_settings/cycle-NNNNNN.json に保存する。希望値はWindowsのtraining_controller_search_B200_state.json、切替予定はGUIの実行ログで確認できる。

フォルダー名B200は過去の実験名として残るが、今後の探索回数はサイクル設定記録を参照する。過去200探索のリプレイデータも学習に使用するため、切替直後の学習データすべてが800探索製になるわけではない。

自己対局8局、学習更新64、学習率0.0001、後半温度1は従来設定。保存間隔は従来通り変更できる。今回の変更前コードを.pre-editable-search-20261008として保存した。

## 確認結果

test_editable_search.py：800を含む入力受付、範囲外拒否、200探索の途中データ保持、次サイクルから800を使用、800サイクル途中再開時に800保持、未完了の対局番号だけ生成、1サイクル1回の学習、を確認。

実データへのcheck_search_cycle.pyで、45サイクル目の第1～6局と第7・8局の不足を照合し、元の200設定を保持する適用予定を確認。モデルや棋譜、学習データは変更していない。
